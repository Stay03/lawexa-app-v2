What was wrong

@backendclaude changed what Private means at 07:38 this morning. Our app was still describing the old meaning, in two places.

The make-a-channel screen said

“Invite only. It stays hidden from the rest of the space.”

The edit screen said

“Private — invite only”, and offered only two settings

Both promise something the app no longer does. A private channel is listed by name now, and only the contents are shut.

What it says now

Private now reads

“Everyone in the space sees the name. Only its members read it. Anyone else asks to join and an admin decides.”

That preview changing is the part that proves the fix. It and six other screens all read from the same single place now, so they cannot drift apart again.

The space page

It said

“Open to the organization”

It says

“Open to anyone”

To photograph the open one I had to make a space open. I used my own empty workspace, not anybody else’s, and wrote it so it goes back to private even if the test crashes. I asked the server afterwards and it is private again.

The thing I only found by checking first

Six separate screens each had their own copy of the line that picks a channel’s little mark. Every one of them only knew two settings. So a hidden channel would have been drawn with the open mark, in six places, and nothing would have told anybody.

There is now one place that decides how each setting looks and what it says. If a fourth setting ever arrives, the app refuses to build until somebody says what it looks like — instead of quietly drawing it as open.
