Asking to join, and inviting by link

The four things you asked for tonight, plus two faults I found while testing them. Nothing is pushed yet.

Start 20:25 UTC · finish 21:35 UTC · 1 hour 10 minutes

Everything below runs against the real server. The pictures are the real app, not drawings.

1 · The old app showed the wrong lock

Three screens in the old app drew a channel's privacy mark with a two-way test: private gets a lock, everything else gets a hash. Since the server grew a third setting, hidden, those screens drew a hidden channel as if it were open to everyone. That is the loudest thing a privacy mark can get wrong, and the old app is what your live users are on.

Was

A hidden channel wore the open mark on three old-app screens.

Now

All three read the same table as the new app. There is one table, in one file, and the compiler stops the build if a fourth setting ever arrives without an answer.

2 · You can now ask to join a private channel

A private channel is listed by name to everyone in the space, but only its members can read it. Until tonight the screen you met was a dead end: it said "ask someone already in it to add you" and gave you nothing to press.

Pressing twice is safe. The server treats a second ask as the same one, so nothing breaks and no error appears.

One thing the server cannot tell us yet

If you reload the page, the screen forgets you asked and offers the button again. The channel the server sends carries nothing about your own waiting request, so there is nothing for the screen to read. Pressing again is harmless, so this is a rough edge and not a fault.

One line for backend: put the viewer's own pending request on the channel, and the screen will say "you asked" straight after a reload.

3 · Invite by link now sits inside Invite people

The link was built, but it lived in a menu at the top of the space. So somebody who pressed Invite people met a form that could only take an email address — which is no use at all for the person this feature exists for: somebody who has never heard of Lawexa and has no account to address.

The link is now under the email field, where the intention already is. Channels get one too, which they never had: a channel invite could only reach people already in the space.

Opening this makes nothing. It shows the link that already exists, so the address you paste today is the same one you pasted last week. A new one is written only when there is none and you press for it.

4 · I ran the two admin panels, and found two faults

The channel waiting list was attached to nothing

The space waiting list was on the space screen. The channel one was written at the same time and put on no screen at all. Nobody noticed because nothing could put a person in it — until tonight, when I added the button that does. Requests would have left, you would have been notified, and no screen in the app could open them.

The links panel was a graveyard

A stopped link is kept on purpose — it is how you answer "who got in through what". But the server sends them mixed in with the working ones, newest first. On a real space that meant six struck-through rows and no working link anywhere on the screen.

5 · One question settled after six days

Since the preview feature landed we did not know whether the server lets a space member open a private channel they are not in. Both answers were handled and neither was written into any wording, because guessing would have told half the readers something false.

I measured it tonight against the live server. The server does release the channel — its name, its member count — and refuses only the messages and the member list. That is what makes "Ask to join" honest: the server has already told them the room is there.

A refusal that gives nothing away is still used for the other case, where we genuinely cannot tell a hidden channel from one that never existed. That screen has no button, on purpose: pressing it would confirm what hidden exists to conceal.

6 · Arthur's keyboard problem — found it, not fixed yet

Arthur sent two pictures tonight. This is not a gap at the bottom. When the keyboard opens on iPhone, the box you type into slides underneath it, so the words he types are hidden. It happens in Safari and in the installed app, which matches: both use the same engine.

The cause is known: iPhone does not shrink the page when the keyboard opens, so anything pinned to the bottom stays where the bottom used to be. The fix is to measure the space the keyboard leaves and lift the box into it.

This was not on tonight's list. Say the word and I will do it — about half a day, and it touches every screen with a box at the bottom.

What I checked before saying it works

  • Types and lint: clean.
  • Full production build: clean.
  • Every screen above opened by driving the real app with a real account, against the live server.
  • Channel links created, previewed with no account at all, and deleted again.

One thing I could not check: a waiting list with somebody in it. That needs a second account in the same space. The panel opens and reports an empty list correctly; the row itself has not been seen with real data.
