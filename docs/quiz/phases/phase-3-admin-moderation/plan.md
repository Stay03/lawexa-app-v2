# Phase 3 — Admin: Question Moderation

> The first **admin-console** slice: a place for staff to police the LLM-generated
> question bank — list/filter, inspect, edit, and change status
> (approve/archive/delete/restore), plus bulk approve/archive.
>
> Builds the admin-side plumbing we deferred in Phase 0. See
> [`../../main-plan.md`](../../main-plan.md).

---

## 1. Goal

Give admins a clean, conventional admin screen to moderate quiz questions:

- **List** questions with filters + pagination.
- **Inspect** a question in full (with the correct answer + usage stats + moderation trail).
- **Edit** a question (fix wording, options, correct answer, difficulty, topic).
- **Status actions**: approve, archive, soft-delete, restore — single and **bulk**.

There is **no "create" screen** — questions are generated by a backend job; the API
exposes no create endpoint. Admins only moderate what's generated.

## 2. Access

These pages live under `app/(admin)/admin/quiz/...`, so the existing
[`(admin)/layout.tsx`](../../../../app/(admin)/layout.tsx) `AdminGuard` already gates
them to **`admin` / `superadmin`**. Researchers can't reach them, and the backend
independently enforces `role:admin` (`403` otherwise) — so nothing extra to build
for access.

## 3. API surface (admin moderation)

Auth: Bearer + `role:admin`. **Note the real path prefix is `/admin/quiz/...`**
(unlike admin-cases which maps to `/cases`). The shared `apiClient` adds `/api`.

| Method | Path | Purpose |
|---|---|---|
| `GET` | `/admin/quiz/questions` | List/filter (paginated) |
| `GET` | `/admin/quiz/questions/{uuid}` | Full detail (incl. soft-deleted; `is_correct` shown) |
| `PATCH` | `/admin/quiz/questions/{uuid}` | Edit (exactly 4 options + `correct_index`) |
| `POST` | `/admin/quiz/questions/{uuid}/approve` | → `approved` (opt. `moderation_notes`) |
| `POST` | `/admin/quiz/questions/{uuid}/archive` | → `archived` |
| `POST` | `/admin/quiz/questions/{uuid}/restore` | un-delete |
| `DELETE` | `/admin/quiz/questions/{uuid}` | soft-delete (`data: null`) |
| `POST` | `/admin/quiz/questions/bulk` | bulk `approve`/`archive` (see §8 — blocked) |

**List filters:** `status` (approved\|archived), `topic_key`, `difficulty` (1–5),
`source_mode` (content\|transcript), `generated_for_user_id`, `with_trashed`,
`date_from`, `date_to`, `per_page` (1–100).

**Edit schema (`lib/validations/admin-quiz.ts`):**
```
question_text   string, required, ≤ ~1000
explanation     string, optional/nullable
difficulty      int, required, 1–5
topic           string, required, ≤ 255
options         array of exactly 4 non-empty strings
correct_index   int, required, 0–3
moderation_notes string, optional, ≤ 2000
```

## 5. Screens

### 5.1 List — `/admin/quiz/questions`
Mirrors `app/(admin)/admin/cases/page.tsx`: `Suspense` + content; URL-driven filter
state; `useDebounce` for any text filter; `AdminPagination`; `Card` layout.

```
┌ Quiz Questions ──────────────────────────────────────────────┐
│  [ status ▾ ] [ difficulty ▾ ] [ source ▾ ] [ topic_key ___ ] │ ← filters (URL-driven)
│  [ ☐ show deleted ]  [ date_from ] [ date_to ]   [ Clear ]    │
│                                                              │
│  ☐  Question (truncated)        Topic   Diff  Status  Rate  ⋯ │ ← header ☐ = select page
│  ☑  Which option best states…   Crim L  Med   approved 0%   ⋯ │
│  ☐  Odit tempora qui qui non?   Crim L  Med   archived —    ⋯ │
│  …                                                           │
│  Showing 1–15 of 342            ‹ Page 1 of 23 ›             │
└──────────────────────────────────────────────────────────────┘
  ⌃ when rows selected: ┌──────────────────────────────────────┐
                        │ 3 selected   [Approve] [Archive]  ✕   │ ← bulk bar (see §8)
                        └──────────────────────────────────────┘
```
- **Columns**: select checkbox, question (truncated, tooltip), topic, difficulty
  (reuse `DifficultyBadge`), status badge (+ "Deleted" if `deleted_at`), `correct_rate`
  (`—` when null), served/answered, generated-for user, created date, row actions (⋯).
- **Row actions** (`DropdownMenu`): View, Edit, Approve/Archive (by current status),
  Delete or Restore (by `deleted_at`).
- **Row click** → detail page.
- **States**: loading skeleton rows, empty ("No questions match"), error + retry.

### 5.2 Detail — `/admin/quiz/questions/[uuid]`
Read-only, `Card`-sectioned (like the case detail):
- **Question** + 4 options with the **correct one marked** (admin sees `is_correct`)
  + explanation.
- **Meta**: topic/topic_key, difficulty, status, course, source_mode,
  generated-for user (name/email), source conversation + generation batch links.
- **Usage**: served / answered / correct / correct_rate.
- **Moderation trail**: reviewed_by, reviewed_at, notes.
- **Header actions**: Edit, Approve/Archive, Delete/Restore (each an
  `AlertDialog` confirm with an optional `moderation_notes` field).

### 5.3 Edit — `/admin/quiz/questions/[uuid]/edit`
`react-hook-form` + `zodResolver(adminQuizQuestionSchema)`, prefilled from detail:
- `question_text` (textarea), `explanation` (textarea), `difficulty` (select 1–5),
  `topic` (input), **4 option rows** (text input each) with a **"correct" radio**
  per row driving `correct_index` (exactly one), `moderation_notes` (textarea).
- Submit → `PATCH`; on success toast + back to detail. `422` → surface field errors.
- Editing updates options **in place** (history stays valid); note in the UI that
  students who already answered will see "updated after you answered."

## 8. Bulk moderation — resolved ✅

Backend updated `/bulk` to accept **`uuid`s** (2026-06-28). The `ids` field now
carries 1–200 question **`uuid`s** — the same `uuid` on list/detail rows:

```json
{ "action": "archive", "ids": ["d7b52c0a-…", "ed65c57f-…"], "moderation_notes": "optional" }
→ 200 { "data": { "affected": 3 } }
```
- `action` is `approve` or `archive` only (delete/restore stay single-uuid).
- A numeric id or unknown/invalid uuid → `422`.

So bulk is a normal feature: select rows (track their `uuid`s) → bulk bar → one
`/bulk` call. No interim fan-out needed.

## 9. Behaviours / gotchas

- `correct_rate` is a **number 0–100 or null** (not a string) — show `—` when null.
- Admin sees `is_correct` on options (list/detail/edit); the **student** never does.
- Edit is **in-place** → past results stay valid; from the edit forward, prior
  answerers see `edited_since_answered` in their results.
- Status/delete/restore accept an optional `moderation_notes` and stamp the trail.
- `with_trashed=true` reveals soft-deleted rows; those show **Restore** (not Delete).
- Bulk is 1–200 ids; `per_page` max is 100, so "select all on page" stays within range.
- All actions are audited server-side; delete returns `{ data: null }`.

## 10. Accessibility

- Table is a real `<table>` (the `Table` primitive); row checkboxes have labels;
  the header checkbox is "select all on page".
- Row actions reachable via keyboard (`DropdownMenu`); dialogs are focus-trapped.
- Status conveyed by text + colour (badge), never colour alone.
